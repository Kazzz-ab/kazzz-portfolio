<Problem>
Picture a small brand with genuinely good products and a shop that works — at home. Then someone in Berlin, or Dubai, or Toronto finds it. They see prices in a currency that isn't theirs and start doing mental maths. A checkout that assumes one country. Copy in one language. A layout that quietly says "local." They don't complain — they just close the tab. The owner never sees the sale that didn't happen; on the dashboard it only ever looks like "overseas visitors don't convert."

That gap is rarely the product, and almost never the price itself — it's everything *around* the price. Buying from a foreign brand you've never heard of is an act of trust, and that trust is won or lost in the first scroll: is this in my money, in my language, does it look like somewhere I'd hand over a card? A storefront that broadcasts "small and local" keeps good products small and local.

Haque Mart is the rebuild of a single-market shop into something an SME *anywhere* could run and be proud of. It quotes every price in the visitor's own currency, speaks their language — right-to-left included — and trades the busy, discount-shouting look of a local shop for the restraint of a brand that expects to be trusted. The goal was narrow and human: make a stranger's first order feel safe.
</Problem>

<Architecture diagram="/diagrams/haque-mart.svg">
The commerce half is a clean headless seam. WordPress + WooCommerce owns the catalogue, inventory, and orders, reached only through WPGraphQL; the Next.js frontend renders product pages on the server. When the WordPress endpoint isn't configured, a curated mock catalogue activates automatically — so the storefront runs, demos, and can be shown to a client with no backend wired at all.

The half that makes it *global* is a thin presentation layer the rest of the app never has to think about. Prices are stored once, as numeric base-currency (USD) amounts; a Currency context converts and formats them to the shopper's currency, and every price on the site renders through a single `<Price>` component — so switching from dollars to euros to dirhams reprices the entire store at once: cards, product page, cart, the free-shipping threshold, checkout. A Locale context resolves copy through a dictionary with English fallback and sets the document's text direction, so Arabic mirrors the whole layout to right-to-left. A shopper picks a region once; currency and language follow.
</Architecture>

<Decisions subtitle="Three decisions that turned a local shop into a global one.">

<Decision
  number="01"
  title="Store one base price, format it per shopper"
  chose="Numeric base-currency (USD) amounts behind a single <Price> render seam"
  rejected="Currency-formatted price strings baked into the CMS, e.g. £24.99"
  why="Roughly a third of cross-border carts are abandoned when prices aren't shown in the buyer's own currency — the friction isn't the amount, it's the mental conversion. Storing one numeric amount and formatting it at render means a single currency switch reprices the whole site instantly, through one component. Formatted strings would have baked a single market into the data itself, and 'add a second currency' would have meant rewriting every component that shows a price."
/>

<Decision
  number="02"
  title="Internationalization as a provider layer, not a translation bolt-on"
  chose="Currency + language + region behind React context, RTL-ready, with a region that presets the other two"
  rejected="A translate plugin layered over the existing single-region storefront"
  why="'Global' is a trust-and-checkout problem, not just a strings problem. Currency, language, and shipping region travel together — a visitor in the UAE wants dirhams, Arabic, and a layout that reads right-to-left. Modelling region as the thing that presets currency and language lets a shopper choose once and have the whole store follow; selecting Arabic flips the document direction and the layout mirrors for free, instead of being a special case bolted on at the end."
/>

<Decision
  number="03"
  title="Premium by subtraction — cut the urgency theatrics"
  chose="Quiet trust signals: verified reviews, real stock counts only, editorial restraint"
  rejected="Countdown timers, 'Only 2 left!', '🔥 14 sold today', rotating flash-sale bars"
  why="A first-time cross-border buyer is already taking a risk on a brand they've never heard of. Fake scarcity and emoji read as a cheap local shop — exactly the signal that scares off a cautious stranger. Removing them did more for how premium and trustworthy the store feels than any feature I could have added. Looking expensive, it turns out, is mostly about what you leave out."
/>

</Decisions>

<Code title="The price a shopper sees is computed in their currency — never hard-coded">
{`// Prices are stored once, as a numeric base-currency (USD) amount.
// The shopper's currency is applied at render — never baked into the data.

// src/lib/i18n/currency.tsx
const meta = CURRENCIES[currency];            // active currency: locale + rate
const format = (usd: number) =>
  new Intl.NumberFormat(meta.locale, { style: "currency", currency: meta.code })
    .format(usd * meta.rate);

// src/components/Price.tsx — the single seam every price flows through
export function Price({ amount }: { amount: number }) {
  const { format } = useCurrency();
  return <span>{format(amount)}</span>;
}

// Switch currency once → every price on the page re-renders.
// $32.00  →  29,44 €  →  £25.28  →  ﷼ 117.44   — same data, the shopper's money.`}
</Code>

<Outcomes>
<Works>
- Multi-currency: eight currencies with live conversion + locale-correct formatting, persisted across visits — every price flows through one `<Price>` seam (cards, product page, cart, checkout, shipping threshold)
- Multi-language with English-fallback `t()` (EN/ES/FR/AR); selecting Arabic flips the entire layout to right-to-left; a region picker presets currency + language together
- Light editorial design system — warm neutrals, a deep teal jewel accent, Fraunces display type — that reads premium rather than "local web shop"
- Headless WooCommerce over WPGraphQL with an automatic mock-catalogue fallback, so the frontend runs and demos with no backend
- Cart + wishlist with localStorage persistence; an internationalized checkout (global country list, payment-method badges) and order confirmation
- Curated product photography, calm scroll motion, and an app-like mobile experience
</Works>
<DoesntYet>
- Real payment processing — checkout is a simulated submit; the payment-method UI is a placeholder where card / Apple Pay / PayPal would wire in
- Exchange rates are a static demo table — production needs a live FX feed (the shape stays identical)
- Translations cover the storefront chrome; product copy stays in its source language — a per-product translation layer is the next step
- No user accounts or order history, and WooCommerce stock changes don't yet trigger revalidation
</DoesntYet>
</Outcomes>

<Lessons>
The thing that made the store feel global wasn't translation — it was showing people their own money before they had to think. Currency is the trust unlock; copy is a distant second. The first time I switched from dollars to euros and watched every price, the cart, and the shipping threshold reprice at once, it stopped feeling like a demo and started feeling like a shop that ships to *you*.

Premium came mostly from subtraction. Pulling out the countdowns, the "Only 2 left," the emoji, and the flash-sale bar did more for how expensive the store looks than any font or photograph — a cautious buyer reads restraint as confidence. The hardest part wasn't adding polish; it was having the discipline to delete the things that were quietly working against trust.

Storing prices as one numeric base amount and routing every render through a single `<Price>` seam is a tiny decision that only reveals its value the moment a second currency exists. Had the prices stayed as formatted strings baked into the data, "add a currency" would have meant touching every component instead of one. The cheapest time to make a thing global is before it has more than one of anything.
</Lessons>
